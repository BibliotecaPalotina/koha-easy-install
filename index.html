Acesso Universal por Navegador

O sistema fica hospedado em uma única máquina servidora. Funcionários e leitores utilizam o Koha diretamente pelo navegador web (Google Chrome, Firefox, Edge, Safari), sem necessidade de instalar programas pesados nos computadores de atendimento ou consulta.

O Koha opera obrigatoriamente através de duas portas de rede padronizadas:

  • Porta 8080 (Staff / Interface Administrativa): Painel restrito dos bibliotecários e atendentes. Utilizada para catalogação bibliográfica no padrão MARC21, controle de circulação (empréstimos e devoluções), cadastro de usuários, gestão de multas e geração de relatórios SQL.
  • Porta 80 (OPAC / Catálogo Público): Página pública voltada aos leitores. Permite consultar o acervo da biblioteca, checar disponibilidade nas estantes, renovar prazos e reservar títulos pela internet.

Gestão de Redes de Bibliotecas: Uma única instalação permite administrar múltiplas unidades físicas (como uma biblioteca central e várias filiais ou salas de leitura escolares). Todas compartilham o mesmo catálogo, mantendo o controle de estoque e regras de circulação individualizados.

Cenário 1: Servidor Físico Dedicado (Ubuntu Server)

Instalação limpa em um computador físico da biblioteca sem sistema operacional prévio.

  • Download da Imagem ISO: Baixe a imagem oficial do Ubuntu Server LTS (versão 22.04 ou 24.04).
  • Criação do Pendrive Bootável: Baixe e instale o BalenaEtcher. Conecte um pendrive de no mínimo 4GB, abra o BalenaEtcher, clique em Flash from file, selecione o arquivo ISO baixado, selecione seu pendrive e clique em Flash!.
  • Ajustes na BIOS da Placa-Mãe: Conecte o computador via cabo de rede no roteador. Ligue o PC pressionando a tecla de acesso à BIOS (Del, F2, F10 ou F12) e configure:
    • Secure Boot: Mude para Disabled.
    • SATA Mode: Garanta que esteja em AHCI.
    • Restore on AC Power Loss / AC Back: Mude para Power On (faz o servidor ligar sozinho se a luz cair e voltar).
    • Fast Boot: Mude para Disabled.
    • Halt On: Mude para No Errors (impede que a BIOS trave o boot por falta de teclado conectado).
  • Instalação do Ubuntu Server: Na aba de boot da BIOS, selecione o pendrive. Durante o instalador:
    • Selecione o idioma e deixe a rede em DHCP automático (via cabo).
    • Particionamento: Escolha Use an entire disk (usar o disco inteiro).
    • Defina o nome do servidor, o nome de usuário e uma senha forte (anote esses dados!).
    • Atenção Crítica: Na tela de pacotes adicionais, marque com a barra de espaço a opção Install OpenSSH server. Sem isso, você não conseguirá acessar a máquina remotamente.
  • Ao terminar, reinicie a máquina, retire o pendrive e faça login com seu usuário e senha. Identifique o IP da máquina com o comando ip a (conforme explicado na Seção 3). Como esta máquina não tem interface gráfica, todo o gerenciamento será feito via SSH pelo PowerShell de outro computador.

Cenário 2: Servidor em Nuvem / VPS

Instalação em um provedor de nuvem (DigitalOcean, Hetzner, AWS, Hostinger, etc.).

  • Crie uma conta na empresa escolhida e configure o método de pagamento.
  • Clique em Create Instance (ou Create Droplet).
  • Sistema Operacional: Escolha Ubuntu Server LTS recente (22.04 ou 24.04).
  • Plano de Hardware (Obrigatório): Selecione um plano com no mínimo 4GB de RAM e 2 vCPUs. Servidores com menos memória travarão durante rotinas pesadas de indexação.
  • Autenticação: Escolha autenticação por senha root ou adicione sua chave SSH pública.
  • Finalize a criação. Em poucos segundos o painel da VPS fornecerá um Endereço de IP público e o usuário de login (normalmente root ou ubuntu). O acesso será feito remotamente a partir do seu terminal ou PowerShell via SSH.

Cenário 3: Computador com Linux Gráfico (Linux Mint ou Ubuntu Desktop)

Instalação em uma máquina com área de trabalho visual para uso direto no computador.

  • Download da ISO:
    • Opção 1 (Recomendada para iniciantes): Download Linux Mint (Cinnamon Edition).
    • Opção 2: Download Ubuntu Desktop.
  • Grave a ISO no pendrive utilizando o BalenaEtcher da mesma forma explicada no Cenário 1.
  • Desative o Secure Boot na BIOS do computador e inicie o sistema pelo pendrive.
  • Na área de trabalho do instalador, dê dois cliques no ícone "Install Linux Mint" (ou Install Ubuntu). O assistente é totalmente visual em português: escolha seu fuso horário, layout do teclado, crie seu nome de usuário e senha.
  • Conclua a instalação e reinicie o PC.
  • Vantagem Operacional deste Cenário: Você NÃO precisa usar SSH! Abra o terminal nativo do sistema pressionando as teclas Ctrl + Alt + T e execute os comandos diretamente nele.

Cenário 4: Windows usando VirtualBox

Execução do Ubuntu Server dentro de uma máquina virtual no Windows.

  • Ativação de Virtualização: Reinicie o Windows, entre na BIOS e ative o suporte a virtualização: procure por Intel Virtualization Technology (VT-x) ou SVM Mode (AMD) e marque como Enabled. Sem isso, o VirtualBox não criará sistemas de 64 bits.
  • Downloads Necessários: Baixe e instale o VirtualBox e baixe a ISO do Ubuntu Server LTS.
  • Criação da Máquina Virtual no VirtualBox:
    • Abra o VirtualBox e clique no botão Novo (New). Nome: Digite Koha-Server.
    • Imagem ISO: Aponte para o arquivo ISO do Ubuntu Server.
    • ATENÇÃO CRÍTICA: Na tela de criação, marque a caixa "Pular Instalação Desatendida" (Skip Unattended Installation). Se você permitir a instalação desatendida, o VirtualBox criará um usuário aleatório e ignorará o OpenSSH, trancando você fora do sistema!
  • Recursos de Hardware: Memória Base (RAM): no mínimo 4096 MB (4 GB). Processadores: aloque ao menos 2 CPUs. Disco Rígido: pelo menos 25 GB.
  • Configuração de Rede (Crucial para funcionar na rede local):
    • Vá em Configurações > Rede.
    • No campo Conectado a:, troque de "NAT" para Placa em modo Bridge (Bridged Adapter).
    • No campo Nome, selecione a placa de rede do seu computador (Wi-Fi ou Ethernet).
    • Por que isso é obrigatório? No modo NAT, o Koha fica isolado. No modo Bridge, seu roteador atribui um IP real para a máquina virtual, permitindo que a rede local acesse o Koha nas portas 8080 e 80.
  • Inicie a VM e siga a instalação manual do Ubuntu Server normalmente, lembrando de marcar o pacote OpenSSH.

Cenário 5: Windows usando WSL2

A forma mais leve de rodar o kernel Linux integrado diretamente dentro do Windows 10 ou 11.

  • Ative a virtualização (VT-x / AMD-V) na BIOS da sua placa-mãe.
  • No menu Iniciar do Windows, pesquise por Ativar ou desativar recursos do Windows e marque: Subsistema do Windows para Linux e Plataforma de Máquina Virtual. Clique em OK e reinicie.
  • No menu Iniciar, procure por PowerShell, clique com o botão direito e selecione Executar como Administrador. Digite o comando abaixo e tecle Enter:
    PowerShell (Administrador)
    wsl --install -d Ubuntu
  • Aguarde o download e instalação. Ao reiniciar, a janela preta do Ubuntu abrirá solicitando que você crie um usuário e uma senha (anote esses dados).
  • Fixe o atalho do Ubuntu na barra de tarefas.
  • Vantagem Operacional deste Cenário: Você NÃO precisa de SSH! Basta abrir o atalho do Ubuntu e colar os comandos diretamente nele. Para que o Koha funcione na rede, basta manter essa janela aberta minimizada.

Quem precisa e quem NÃO precisa de SSH?

Cenários 3 e 5 (Linux Gráfico / WSL2): Você está trabalhando diretamente na máquina. NÃO precisa de SSH. Abra o terminal na sua tela (Ctrl + Alt + T no Linux ou atalho do Ubuntu no Windows) e execute todos os comandos por ele.

Cenários 1, 2 e 4 (Servidor Físico / VPS / VirtualBox): O servidor está rodando em modo texto sem monitor próprio ou em segundo plano. Você precisa conectar nele através do PowerShell de outro computador usando SSH.

Como identificar o IP do Servidor (Cenários 1, 2 e 4)

No terminal do Linux, execute o comando:

Terminal Linux
ip a

Como localizar seu IP na resposta: Procure pela interface de rede principal (ex: eth0, enp3s0 ou wlan0). Ignore a interface lo. Na linha que começa com inet, o número antes da barra é o seu IP (ex: se aparecer inet 192.168.1.50/24, o IP é 192.168.1.50). Se estiver em uma VPS, o IP é o endereço público fornecido pelo painel.

Conexão Remota via PowerShell (Apenas Cenários 1, 2 e 4)

No computador Windows que você usa para trabalhar, abra o PowerShell e digite o comando abaixo (substitua nomedousuario pelo nome do usuário que você criou no servidor e ipdoservidor pelo IP real que você descobriu):

PowerShell
ssh nomedousuario@ipdoservidor

Nota: Na primeira conexão, o PowerShell perguntará se você confia no servidor (Are you sure you want to continue connecting?). Digite yes e aperte Enter. Depois, digite sua senha (ela não aparece enquanto você digita).

Terminal Linux
sudo curl -fsSL "https://raw.githubusercontent.com/BibliotecaPalotina/koha-easy-install/refs/heads/main/installer" -o /usr/local/bin/options.sh


sudo chmod +x /usr/local/bin/options.sh
sudo options.sh



O comando sudo options.sh fica registrado permanentemente no PATH do servidor. Sempre que precisar realizar tarefas de manutenção, gerenciar backups ou consultar status, basta invocá-lo.

  Opção 1
  
Instalar o servidor Koha

  
Executa a instalação completa da stack LAMP e do Koha. Configura locales UTF-8, sincronização NTP via systemd-timesyncd, memória SWAP de 4GB com proteção de espaço em disco, instalação de dependências essenciais (incluindo glabels para confecção de etiquetas), configuração do Apache (portas 80 e 8080), templates Memcached e isolamento da instância library.






  Opção 2
  
Ver credenciais de acesso

  
Extrai de forma limpa e direta a senha mestre do banco contida no koha-conf.xml e exibe as URLs ativas do OPAC e Staff, sem necessidade de ler manualmente o arquivo de configuração ou abrir o diretório root.






  Opção 3
  
Restaurar acervo de um backup

  
Restauração com rede de segurança. Antes de alterar o banco, o sistema valida a integridade do arquivo compactado com gzip -t e analisa a presença de declarações SQL. Em seguida, gera um dump de segurança do banco atual (PRE-RESTAURACAO). Se a importação falhar, o script oferece reversão instantânea automática para o estado anterior.






  Opção 4
  
Gerar backup manual agora

  
Abre um seletor visual de diretórios, permitindo escolher qualquer pasta local ou pendrive montado (como /media ou /mnt). Utiliza mysqldump --single-transaction --quick em charset utf8mb4, evitando travamento de tabelas em ambientes em produção.






  Opção 5
  
Testar o último backup (Restauração de Ensaio)

  
Aplica o princípio de validação operacional: importa o arquivo de backup mais recente em um banco temporário isolado (koha_teste_restauracao), afere a contagem de tabelas, registros bibliográficos e leitores, e descarta o banco temporário. Garante que seu backup não está corrompido sem afetar os dados em uso.






  Opção 6
  
Instalar idiomas do Koha

  
Apresenta um menu com dezenas de traduções oficiais empacotadas. Realiza o download via koha-translate, reinicia o cache de templates do Memcached, reinicia o Plack e permite habilitar o idioma imediatamente nas preferências globais de sistema.






  Opção 7
  
Alternar motor de busca (Zebra ↔ Elasticsearch)

  
Gerencia a transição segura entre motores de indexação:

  
    
    
  • Zebra → Elasticsearch: Configura nós locais do Elasticsearch 7, ajusta a memória JVM Heap dinamicamente, instala o plugin analysis-icu, injeta o bloco <elasticsearch> no XML via Python, cria serviço systemd dedicado com watchdog e dispara a reindexação total.
    • 
    
  • Elasticsearch → Zebra: Desativa daemons Java, remove o bloco XML com parser atômico, remove travas LCK antigas, restaura permissões de diretórios e ativa cron jobs incrementais de 2 minutos.
    • 
  






  Opção 8
  
Reparar / reconstruir indexação

  
Diagnostica inconsistências entre o número de registros no banco e os documentos indexados. Permite destravar filas presas, remover arquivos PID ou LCK corrompidos, reiniciar daemons de indexação e disparar rebuilds forçados em segundo plano.

  Opção 10
  
Configurar backup em nuvem (Rclone)

  
Integra o envio automatizado dos backups diários para o Google Drive ou outros serviços em nuvem. Utiliza fluxo expresso que gera o token de autorização, valida permissões de escrita na pasta remota e vincula o remote ao arquivo de configuração global /etc/koha-easy-install/backup.conf.






  Opção 11
  
Tarefas agendadas (Horários do Cron)

  
Abre o arquivo central /etc/cron.d/koha_tasks no editor nano com backup preventivo. Garante a integridade da declaração obrigatória de PATH para execução do koha-shell, evitando falhas silenciosas de tarefas automáticas.






  Opção 12
  
Configurar e-mails e avisos (SMTP)

  
Instala módulos de autenticação SASL, agenda o processamento automático da fila de avisos e notificações de atraso, e orienta a integração com provedores SMTP modernos (como Gmail via senhas de aplicativo), preservando a segurança de credenciais.






  Opção 13
  
Criar superbibliotecário

  
Criação segura de administradores de emergência via terminal. O hash criptográfico da senha é processado via STDIN com o módulo interno do Koha (Koha::AuthUtils), garantindo que a senha em texto puro nunca seja exposta em logs de auditoria ou no comando ps. O nome de usuário recebe tratamento rigoroso contra injeção SQL.






  Opção 14
  
Acesso externo (Cloudflare Tunnel)

  
Permite colar diretamente o comando ou token gerado no painel Cloudflare Zero Trust. Instala os repositórios oficiais, implanta o conector cloudflared e ativa o serviço do túnel em nível de sistema operacional.






  Opção 15
  
Certificado SSL gratuito (Let's Encrypt)

  
Configura o certbot integrado com o Apache para emissão e renovação automática de certificados HTTPS convencionais para servidores com IP público estático e portas abertas.






  Opção 16
  
Ativar SIP2 e Z39.50

  
Habilita os serviços e daemons para integração externa: o protocolo Z39.50 (porta 2100) para catalogação cooperativa entre bibliotecas e o protocolo SIP2 (porta 6001) para conexão de totens de autoatendimento.






  Opção 17
  
Relógio e fuso horário

  
Menu didático para ajuste de fusos horários regionais e ressincronização NTP, reiniciando o cron para evitar cobranças de multas ou agendamentos em horários distorcidos.






  Opção 18
  
Central de segurança

  
Permite monitorar tentativas de invasão bloqueadas pelo Fail2ban, isolar o acesso à porta administrativa 8080 apenas para a rede local ou IP de gerência, auditar regras do firewall UFW e rotacionar a senha mestre do MariaDB de maneira automática com atualização síncrona do XML do Koha.






  Opção 19
  
Atualizar sistema e schemas

  
Executa a atualização de pacotes do Debian/Ubuntu e do repositório estável do Koha, disparando o utilitário koha-upgrade-schema para garantir que migrações de banco de dados acompanhem a versão mais nova do software.






  Opção 20
  
Plugins do Koha

  
Habilita ou desabilita o ecossistema de plugins do Koha. Utiliza parser Python para injetar com segurança a flag <enable_plugins>1</enable_plugins> no XML de configuração e corrige permissões da pasta de plugins no sistema de arquivos.






  Opção 21
  
Validar o sistema completo

  
Bateria completa de diagnósticos automatizados: audita serviços em execução, portas de escuta TCP, respostas de código HTTP, formação estrutural de arquivos XML com xmllint, integridade e data dos arquivos de backup e consistência de tabelas SQL, gerando relatório detalhado com exportação para log.






  Opção 22
  
Status detalhado

  
Painel de telemetria rápida: exibe o estado operacional de todos os serviços (Apache, MariaDB, Memcached, Plack, Zebra, Elasticsearch, Cloudflared), fila de jobs pendentes, consumo de memória RAM, espaço livre em disco e data do último backup efetuado.






  Opção 23
  
Atualizar este painel

  
Rotina de autoatualização atômica: baixa a versão mais recente do script a partir do repositório no GitHub para um arquivo temporário, submete o arquivo à validação de sintaxe rigorosa com bash -n e substitui o arquivo original apenas se a integridade for confirmada.






  Opção 24
  
Reiniciar o servidor

  
Envia sinal limpo de reboot para o sistema operacional após confirmação expressa do operador, permitindo a reinicialização de rotina com fechamento seguro de conexões de banco.






  Opção 25
  
Sair

  
Encerra a interface do painel, restaurando os timers do APT e retornando ao terminal nativo do sistema com código de saída limpo.

Passo 4: Indexação no Google e Ajustes de Preferências do Koha


Acesse o painel administrativo Staff do Koha em Administração > Preferências do Sistema e sincronize as seguintes chaves:


    
  
  • OpacBaseUrl: Insira a URL pública HTTPS do catálogo (ex: https://biblioteca.dpdns.org).
    • 
  
  • StaffBaseUrl: Insira a URL pública HTTPS da administração (ex: https://adm.biblioteca.dpdns.org).
    • 
  
  • LibraryName: Digite o nome oficial da biblioteca para exibição nos resultados de busca.
    • 
  
  • OpacMetaRobots: Certifique-se de que a indexação não está bloqueada por diretivas noindex.
    •

Manual Completo de Instalación y Configuración de Koha

Guía estructurada con enfoque en estabilidad operativa: preparación minuciosa del sistema operativo en 5 escenarios, ejecución atómica en una sola línea y uso exhaustivo de las 25 funciones de Koha Easy Install (Panel Interactivo).

1. Arquitectura y Funcionamiento de Koha

Koha es el primer sistema integrado de gestión de bibliotecas (ILS) de código abierto del mundo. Opera nativamente sobre el stack corporativo LAMP (Linux, Apache, MariaDB y Perl), funcionando como un servidor centralizado que atiende tanto la operativa interna del personal como las consultas del catálogo público.

Topología en Dos Puertos Independientes

A diferencia de aplicaciones web convencionales que agrupan las áreas pública y administrativa bajo una misma ruta URL, Koha aísla estrictamente sus servicios en dos puertos TCP dedicados en el servidor web Apache:

Entorno Puerto Predeterminado Usuarios Destino Alcance y Capacidades del Módulo
Staff Client (Intranet) TCP 8080 Bibliotecarios, Catalogadores y Administradores Catalogación bibliográfica y de autoridades en MARC21, circulación (préstamos, devoluciones, renovaciones rápidas con código de barras), adquisiciones, informes SQL de gestión, administración de multas, parámetros globales y servicios SIP2/Z39.50.
OPAC (Catálogo Público) TCP 80 Usuarios, Estudiantes, Investigadores y Comunidad Interfaz pública de búsqueda visual, navegación por facetas dinámicas, reserva de ejemplares, renovaciones en línea desde el autoservicio del usuario, listas bibliográficas y acceso a documentos digitales.

Esta separación física en puertos distintos permite políticas de seguridad precisas: el puerto 80 (OPAC) puede exponerse libremente a internet para consulta pública, mientras que el puerto 8080 (Staff Client) se mantiene restringido a subredes internas de la biblioteca o se accede mediante túneles criptográficos autenticados.

2. Preparación del Sistema Operativo (5 Escenarios)

Koha está diseñado nativamente para distribuciones Debian y Ubuntu. Siga rigurosamente únicamente el escenario correspondiente a su infraestructura:

Escenario 1: Servidor Físico Dedicado (Ubuntu Server)

Instalación de producción nativa en una máquina física (ordenador de sobremesa o servidor en rack) dedicada exclusivamente a la biblioteca.

  • Descarga de la ISO: Obtenga la imagen oficial Ubuntu Server LTS desde el sitio web de Canonical.
  • Grabación de la Memoria USB con BalenaEtcher: Conecte una memoria USB de al menos 4 GB en su equipo de trabajo. Abra BalenaEtcher, pulse Flash from file, seleccione la ISO de Ubuntu Server, elija la unidad USB y confirme la grabación.
  • Parametrización de BIOS/UEFI: Conecte el cable de red Ethernet al servidor. Al encender el equipo, presione la tecla de Setup (habitualmente F2, Del o F12) y configure:
    • Secure Boot: Disabled (evita bloqueos de módulos del kernel).
    • SATA Controller Mode: AHCI.
    • Restore on AC Power Loss: Power On (hace que el servidor se encienda solo tras un corte de energía).
    • Fast Boot: Disabled.
    • Halt On: No Errors (evita bloqueos en el arranque si no hay teclado conectado).
  • Instalador de Ubuntu Server:
    • Conecte la unidad USB, inicie el sistema desde ella y configure idioma y teclado.
    • Mantenga la interfaz de red por DHCP automático cableado.
    • En Guided storage configuration, marque Use an entire disk.
    • Defina el nombre del servidor, nombre de usuario (ej: administrador) y una contraseña robusta.
    • OBLIGATORIO: En la pantalla de paquetes adicionales, desplácese hasta Install OpenSSH server y pulse la barra espaciadora para marcar la opción con [X]. Sin esto, no podrá acceder remotamente.
  • Finalice la instalación, retire la unidad USB y reinicie el servidor.

Escenario 2: Servidor en la Nube / VPS (Hetzner, DigitalOcean, AWS, etc.)

Entorno en centro de datos de alta disponibilidad, idóneo para bibliotecas sin infraestructura local continua.

  • Cree una cuenta en el proveedor seleccionado y configure la facturación.
  • Inicie la creación de una nueva instancia virtual (Droplet / Instancia de Cómputo).
  • Sistema Operativo: Elija estrictamente Ubuntu 22.04 LTS o Ubuntu 24.04 LTS (64-bit).
  • Hardware Mínimo Obligatorio: Seleccione un plan con al menos 2 vCPUs y 4 GB de RAM. Las instancias con solo 1 GB o 2 GB se bloquearán durante los procesos de reindexación y agotarán la memoria de Apache/Plack.
  • Autenticación: Configure una contraseña de root robusta o agregue su clave pública SSH.
  • Una vez aprovisionado el servidor, anote la dirección IPv4 pública proporcionada en el panel del proveedor.

Escenario 3: Ordenador con Linux de Escritorio (Linux Mint o Ubuntu Desktop)

Instalación en un ordenador con entorno gráfico que funcionará simultáneamente como terminal de atención y servidor de Koha.

  • Descargue Linux Mint (Cinnamon Edition) o Ubuntu Desktop LTS.
  • Grabe la imagen ISO en una memoria USB con BalenaEtcher.
  • Inicie el equipo desde la unidad USB y haga doble clic en el instalador gráfico del escritorio.
  • Complete la instalación visual en español, definiendo usuario y contraseña de administrador.
  • Ventaja Operativa: No es obligatorio el uso de SSH. Abra el terminal nativo pulsando Ctrl + Alt + T y ejecute los comandos directamente en pantalla.

Escenario 4: Windows con Máquina Virtual (VirtualBox)

Ejecución de Ubuntu Server dentro de una máquina virtual sobre un sistema anfitrión Windows.

  • Virtualización en BIOS: Reinicie Windows, acceda a la BIOS/UEFI y active Intel Virtualization Technology (VT-x) o SVM Mode (AMD).
  • Instale VirtualBox y descargue la imagen ISO de Ubuntu Server LTS.
  • Creación de la Máquina Virtual:
    • Pulse Nuevo (New). Nombre: Koha-Server. Tipo: Linux / Ubuntu (64-bit).
    • Seleccione el archivo ISO de Ubuntu Server descargado.
    • AVISO CRÍTICO: Marque la casilla Omitir instalación desatendida (Skip Unattended Installation). La instalación desatendida asigna credenciales genéricas y omite la instalación de OpenSSH, impidiendo el acceso posterior.
    • Asigne al menos 4096 MB (4 GB) de RAM y 2 núcleos de CPU. Configure el disco virtual con un mínimo de 25 GB.
  • Configuración Obligatoria de Red (Modo Puente):
    • En la configuración de la máquina virtual, abra la pestaña Red (Network).
    • Cambie Conectado a: de NAT a Adaptador puente (Bridged Adapter).
    • Seleccione su tarjeta de red física activa (Ethernet o Wi-Fi). Esto hace que el router asigne una IP propia a la VM, quedando visible para el resto de ordenadores de la biblioteca.
  • Inicie la máquina virtual y complete la instalación manual de Ubuntu Server asegurándose de marcar OpenSSH.

Escenario 5: Windows 10/11 con Subsistema de Linux (WSL2)

Integración nativa del kernel Linux gestionada por Windows, sin necesidad de software de virtualización pesado.

  • Asegúrese de que la virtualización por hardware (VT-x / AMD-V) esté activa en la BIOS.
  • Abra el menú Inicio de Windows, escriba PowerShell, haga clic derecho y seleccione Ejecutar como Administrador.
  • Ejecute el comando de despliegue automatizado:
    PowerShell (Admin)
    wsl --install -d Ubuntu
  • Al finalizar, reinicie el ordenador. La ventana del terminal de Ubuntu se abrirá solicitando crear un usuario y una contraseña (anote estos datos).
  • Operación Continua: No requiere SSH. Ejecute los comandos directamente en la ventana de Ubuntu. Mantenga esa ventana minimizada en segundo plano para que los servicios de Koha permanezcan activos.

3. Acceso al Terminal y Conexión SSH

Regla de Acceso: Si instaló en Linux de Escritorio (Escenario 3) o en WSL2 (Escenario 5), abra el terminal en su pantalla y pase directamente a la Sección 4. Si instaló en un Servidor Físico (Escenario 1), VPS (Escenario 2) o VirtualBox (Escenario 4), acceda vía SSH desde otro ordenador.

Identificación de la Dirección IP Local del Servidor

En el terminal de su servidor Linux, ejecute:

Terminal del Servidor
ip a

Ubique la interfaz de red principal (ej: eth0, enp3s0 o wlan0). En la línea que comienza con inet, observe el número antes de la barra diagonal (ej: en inet 192.168.1.105/24, la IP es 192.168.1.105). En un VPS, utilice la IP pública indicada en el panel del proveedor.

Conexión Remota vía PowerShell (Windows) o Terminal (macOS/Linux)

En su equipo de trabajo habitual, abra PowerShell o el terminal y conéctese:

Equipo de Trabajo Local
ssh usuario_del_servidor@ip_del_servidor

Ejemplo: ssh administrador@192.168.1.105. En la primera conexión, escriba yes y pulse Enter. Introduzca la contraseña del servidor (los caracteres no se mostrarán por seguridad).

4. Descarga e Inicio del Panel Interactivo

Ejecute este comando atómico en una sola línea encadenada con &&. Descarga de forma segura el script oficial, aplica permisos de ejecución en disco e inicia la suite de administración de inmediato:

Comando Único de Inicialización
sudo curl -fsSL "https://raw.githubusercontent.com/BibliotecaPalotina/koha-easy-install/refs/heads/main/installer" -o /usr/local/bin/options.sh && sudo chmod +x /usr/local/bin/options.sh && sudo options.sh
Accesos Posteriores al Sistema: El ejecutable queda instalado permanentemente en /usr/local/bin/options.sh. Para gestionar su servidor en el futuro, no necesitará descargar nada más de internet: solo escriba en el terminal:

sudo options.sh

5. Guía Detallada de las 25 Funciones del Panel

Opción 1

Instalar el servidor Koha (Despliegue Base Automatizado)

Realiza la preparación integral de la máquina para ejecutar Koha de forma desatendida y sin errores manuales:

  • Prevalidación de Requisitos: Verifica privilegios de root, compatibilidad de la distribución Debian/Ubuntu, resolución DNS con los repositorios oficiales de Koha Community, conexión HTTPS y comprueba que los puertos 80 y 8080 estén libres.
  • Configuración Regional y Sincronización Horaria: Configura la codificación obligatoria UTF-8 (pt_BR.UTF-8 y en_US.UTF-8) y sincroniza el reloj del servidor con servidores NTP atómicos mediante systemd-timesyncd.
  • Asignación de Memoria Virtual (SWAP de 4 GB): Crea y activa un archivo de swap permanente de 4 GB con permisos 600 en /etc/fstab, evitando caídas de Apache o MariaDB por falta de memoria RAM física (Out-Of-Memory Killer).
  • Protección contra Bloqueos de APT: Desactiva temporizadores ocultos de actualización en segundo plano de Ubuntu (como unattended-upgrades) que bloquean DPKG e implementa reintentos automáticos ante caídas de conexión.
  • Dependencias Esenciales: Instala utilidades indispensables para bibliotecas como glabels (imprescindible para imprimir etiquetas de tejuelo y códigos de barras), rclone, fail2ban, memcached y librerías de análisis XML.
  • Repositorios y Claves GPG Oficiales: Incorpora las firmas digitales y repositorios oficiales de Koha Community stable y Elasticsearch 7.x.
  • Instancia 'library' Aislada: Configura la base de datos en MariaDB, aplica plantillas globales en koha-sites.conf, vincula los hosts virtuales en Apache, genera contraseñas seguras y arranca Plack junto con el demonio de Zebra.
Opción 2

Ver credenciales de acceso

Extrae de forma limpia las credenciales maestras desde /etc/koha/sites/library/koha-conf.xml. Muestra el usuario de base de datos (koha_library), la contraseña generada durante la instalación y las URLs de acceso formateadas con la IP real del servidor. Guarda además esta información en el archivo protegido /root/credenciais_koha.txt con permisos restrictivos 600 (solo accesible por root).

Opción 3

Restaurar acervo de un backup (Con Red de Seguridad)

Proceso avanzado de restauración para copias de seguridad SQL (.sql o .sql.gz) que contienen catálogo, usuarios e historial de préstamos:

  • Explorador de Archivos Integrado: Muestra un navegador en el terminal para localizar el archivo en cualquier carpeta del disco o memorias USB montadas (/media o /mnt).
  • Prueba Previa de Integridad: Comprueba el archivo contra fallos de compresión con gzip -t y verifica la presencia de sentencias SQL válidas antes de alterar cualquier tabla.
  • Copia de Seguridad Preventiva (Rollback): Antes de vaciar la base de datos actual, genera automáticamente una copia de respaldo del estado previo (PRE-RESTAURACAO_fecha.sql.gz). Si el archivo importado falla o tiene menos de 50 tablas, el script ofrece revertir los cambios de inmediato para no perder información.
  • Actualización de Esquema y Reindexación: Ejecuta koha-upgrade-schema para adaptar bases antiguas a la versión actual de Koha, limpia cachés de Memcached y reconstruye los índices del motor de búsqueda activo (Zebra o Elasticsearch).
Opción 4

Generar backup manual ahora

Genera una copia de seguridad verificada bajo demanda. Abre el Selector de Directorios para elegir la carpeta de destino. El volcado se efectúa con los parámetros --single-transaction --quick --routines --triggers en juego de caracteres utf8mb4, garantizando que la circulación de la biblioteca no sufra bloqueos de tablas durante el proceso.

Opción 5

Probar el último backup (Restauración de Ensayo)

Aplica la regla de oro de la administración de sistemas: una copia de seguridad solo existe si se puede restaurar. Localiza el volcado automático más reciente en /var/backups/koha_sql, crea una base de datos temporal aislada (koha_teste_restauracao), descomprime el archivo y realiza la importación completa. Comprueba el recuento de tablas, registros bibliográficos y usuarios antes de destruir la base de pruebas. Los datos reales en producción no sufren ninguna alteración.

Opción 6

Instalar idiomas de Koha (Paquetes Internacionales)

Ofrece un catálogo con más de 70 paquetes de idiomas oficiales mantenidos por la comunidad internacional de Koha (incluyendo Español es-ES, Portugués pt-PT, Inglés Británico en-GB, Francés fr-FR, Italiano, Alemán, etc.):

  • Descarga y compila los paquetes de traducción mediante koha-translate --install.
  • Reinicia Memcached y los procesos de Plack para registrar de inmediato las nuevas plantillas.
  • Ofrece activar el idioma directamente en las preferencias globales (language y OPACLanguages), mostrando el selector de idioma en el pie del OPAC y en el acceso del personal.
Opción 7

Alternar motor de búsqueda (Zebra ↔ Elasticsearch)

Permite alternar entre los dos motores de búsqueda compatibles con Koha garantizando la integridad de datos y configuración:

  • Zebra: Motor clásico C++ integrado. Muy ligero (consume cerca de 1,5 GB menos de RAM), idóneo para servidores con 4 GB de memoria. Utiliza una cola incremental periódica.
  • Elasticsearch: Motor moderno empresarial desarrollado en Java. Recomendado para servidores con 8 GB o más de RAM. Brinda facetas dinámicas en tiempo real, tolerancia a errores ortográficos (fuzzy search) y alta velocidad en acervos extensos.
  • Transición Segura: Modifica koha-conf.xml mediante un analizador atómico en Python, calibra la memoria JVM Heap de Elasticsearch según la RAM disponible, genera los índices e instala un servicio systemd dedicado (koha-es-indexer@library) con un watchdog programado cada 5 minutos para evitar que la indexación se detenga.
Opción 8

Reparar / reconstruir indexación

Herramienta correctiva y preventiva para situaciones en las que los registros catalogados no se visualizan en los resultados de búsqueda:

  • Para Elasticsearch: Comprueba la respuesta de la API en el puerto 9200, valida el bloque en el archivo XML, examina los trabajos pendientes en cola y contrasta el número de documentos con los registros de MariaDB. Permite forzar una reconstrucción completa (koha-elasticsearch --rebuild -d library) y cancelar procesos huérfanos.
  • Para Zebra: Termina procesos bloqueados de zebrasrv, elimina archivos de bloqueo residuales (.LCK y .pid), restablece permisos para el usuario de Koha y reconstruye los índices desde cero (koha-rebuild-zebra -f -v -b -a -r library).
Opción 9

Dimensionar el servidor (Optimización de Memoria)

Ajusta el rendimiento del sistema en base a la memoria RAM física disponible. Calibra simultáneamente los parámetros PLACK_WORKERS (procesos concurrentes para la web), memcached (tamaño de caché de sesiones y plantillas) y innodb_buffer_pool_size (memoria asignada a MariaDB para retener el catálogo en RAM):

Perfil Capacidad del Equipo Workers de Plack Caché Memcached Buffer Pool InnoDB
Perfil 1 Menos de 4 GB RAM 2 workers 64 MB 512 MB
Perfil 2 4 a 8 GB RAM 3 workers 128 MB 768 MB
Perfil 3 8 a 16 GB RAM 4 workers 128 MB 1 GB
Perfil 4 Más de 16 GB RAM 6 workers 256 MB 2 GB

Reversión Automática: Si selecciona un perfil superior al tolerado por el hardware y MariaDB no consigue arrancar, el script anula el cambio de inmediato y restaura el estado funcional previo sin interrumpir el servicio.

Opción 10

Configurar backup en la nube (Google Drive vía Rclone)

Protege las copias de seguridad de la biblioteca enviándolas de forma externa y cifrada:

  • Modo Expreso (Google Drive): Facilita la vinculación remota. Genera en pantalla un comando de autorización externa (rclone authorize "drive" "..."). Solo debe copiarlo, ejecutarlo en su ordenador de trabajo (donde disponga de navegador), autorizar la cuenta de Google de la biblioteca y pegar el token obtenido de vuelta en el servidor.
  • Modo Manual: Vincula proveedores como OneDrive, Dropbox, Amazon S3, Google Cloud Storage, SFTP o Nextcloud a través del asistente clásico de Rclone.
  • Validación y Prueba Inmediata: Crea las carpetas remotas (Backup_SQL_Koha y Backup_MARC_Koha), registra las variables en /etc/koha-easy-install/backup.conf y permite realizar un envío de prueba al instante.
Opción 11

Tareas programadas (Horarios de Cron)

Abre el archivo central de cron (/etc/cron.d/koha_tasks) con el editor Nano previa copia de seguridad. Los campos de programación están detallados en comentarios de cabecera. Cuenta con un sistema de autocorrección: si accidentalmente elimina la línea de PATH, el panel la reincorpora antes de reiniciar cron para que las utilidades de koha-shell nunca fallen en silencio.

Opción 12

Configurar correos y avisos (SMTP)

Instala las librerías SASL necesarias y programa el envío diario de avisos de vencimiento y procesamiento de la cola de mensajes (a las 08:00 y 08:05). Proporciona las instrucciones necesarias para configurar servidores SMTP salientes (como Google Workspace, Outlook o servidores locales) en el panel de Koha con soporte para STARTTLS y contraseñas de aplicación.

Opción 13

Crear superbibliotecario (Acceso Administrativo)

Crea nuevos administradores generales directamente desde la línea de comandos, útil si ha extraviado la contraseña de la interfaz web:

  • Identifica de forma automática la biblioteca y la categoría administrativa registradas en la base de datos.
  • Valida que el nombre de usuario contenga caracteres alfanuméricos seguros y aplica escape de comillas para prevenir inyecciones SQL.
  • Exige contraseñas de al menos 8 caracteres con validación de coincidencia.
  • Cifrado Seguro mediante STDIN: Genera el hash de la contraseña en Perl mediante la librería interna de Koha (Koha::AuthUtils::hash_password). La clave se suministra por entrada estándar, impidiendo que quede guardada en el historial de Bash (history) o sea visible en listas de procesos (ps aux).
Opción 14

Acceso externo (Cloudflare Tunnel Zero Trust)

Permite exponer el catálogo en internet sin requerir IP pública estática y sin necesidad de abrir puertos en el router de la biblioteca. Descarga y activa el conector oficial cloudflared mediante el token generado en Cloudflare, dejándolo activo como servicio en segundo plano con arranque automático.

Opción 15

Certificado SSL gratuito (Let's Encrypt / Certbot)

Orientado a servidores convencionales que cuentan con IP pública fija directa y puerto 80 accesible. Instala certbot junto con el módulo de Apache para gestionar certificados HTTPS con renovación automática.

Opción 16

Activar protocolos SIP2 y Z39.50

Abre los puertos en el cortafuegos e inicializa los servicios estándar de interoperabilidad:

  • Servidor Z39.50 (Puerto 2100): Facilita que otras bibliotecas consulten y descarguen registros bibliográficos de su acervo.
  • Protocolo SIP2 (Puerto 6001): Permite la conexión de máquinas de autopréstamo, arcos de seguridad antihurto y estaciones de devolución RFID.
Opción 17

Reloj y zona horaria

Menú interactivo para cambiar la zona horaria del servidor (con accesos directos a zonas horarias de España y Latinoamérica). Al confirmarse, reinicia cron de inmediato para evitar que las devoluciones generen multas indebidas por desfases de horario.

Opción 18

Centro de seguridad

Auditoría y refuerzo de seguridad del servidor:

  • Estado de Fail2ban: Informa sobre bloqueos de intentos de intrusión por fuerza bruta en SSH y Apache.
  • Cortafuegos del Puerto Staff (8080): Limita el acceso al puerto 8080 exclusivamente a localhost (127.0.0.1) y subredes privadas (192.168.x.x y 10.x.x.x), bloqueando accesos no autorizados desde internet.
  • Rotación de Contraseña de Base de Datos: Genera una clave aleatoria robusta de 24 caracteres, actualiza el usuario en MariaDB con ALTER USER, modifica koha-conf.xml, actualiza los registros de credenciales y reinicia Plack, verificando la respuesta HTTP para validar el cambio.
  • Reglas de UFW: Lista las políticas activas de puertos en el cortafuegos.
Opción 19

Actualizar sistema y esquemas

Aplica actualizaciones de paquetes estables del sistema operativo y del canal oficial de Koha. Ejecuta las migraciones de base de datos con koha-upgrade-schema library, limpia paquetes obsoletos e inicia la validación general para comprobar la estabilidad del sistema tras la actualización.

Opción 20

Plugins de Koha

Activa o desactiva la arquitectura de plugins externos de Koha. Usa un script en Python para editar koha-conf.xml de manera atómica inyectando <enable_plugins>1</enable_plugins>, ajusta las preferencias correspondientes en la base de datos y establece permisos en /var/lib/koha/library/plugins.

Opción 21

Validar el sistema completo

Módulo de diagnóstico integral con informe de texto. Evalúa la conectividad de red, resolución de nombres DNS, servicios en ejecución, puertos TCP a la escucha, respuestas HTTP locales (80 y 8080), validez del XML de Koha con xmllint, tareas de cron, estado de las copias de seguridad y políticas de cortafuegos.

Opción 22

Estado detallado

Panel de supervisión en tiempo real: presenta en una sola ventana el estado de Apache, MariaDB, Memcached, Plack, Zebra, Elasticsearch y Cloudflared, el motor de búsqueda en uso, tareas pendientes en cola, memoria en uso, almacenamiento en disco y la fecha del último backup.

Opción 23

Actualizar este panel

Mecanismo de autoactualización atómica: descarga la versión más reciente del script desde GitHub en /tmp, comprueba su sintaxis mediante bash -n y, solo si no contiene errores, sustituye el archivo en /usr/local/bin/options.sh, conservando una copia de respaldo con fecha de la versión previa.

Opción 24

Reiniciar el servidor

Realiza un reinicio ordenado del sistema operativo tras solicitar confirmación, asegurando el cierre adecuado de conexiones y el volcado de cachés de disco de MariaDB.

Opción 25

Salir

Cierra la interfaz interactiva, reactiva los temporizadores de actualización de APT en segundo plano y devuelve el control al terminal de Linux de manera limpia.

6. Finalización del Asistente Web en el Navegador

Abra el navegador en su ordenador de trabajo y acceda al puerto de administración 8080:

  • Escenarios 1, 2 y 4 (Servidor Físico / VPS / VirtualBox): Navegue a http://ip_del_servidor:8080 (ej: http://192.168.1.105:8080).
  • Escenarios 3 y 5 (Linux de Escritorio / WSL2): Acceda directamente a http://localhost:8080.

Complete los pasos del asistente:

  1. Autenticación Inicial: Usuario: koha_library | Contraseña: Pegue la contraseña maestra generada en la Opción 1 (si no la recuerda, consúltela en la Opción 2 del panel).
  2. Selección de Idioma: Seleccione el idioma de su preferencia y pulse Continuar.
  3. Comprobación de Módulos y Formato: Valide las dependencias y escoja el formato estándar internacional MARC21.
  4. Estructuras MARC21: Conserve seleccionadas las plantillas predeterminadas de catalogación. PASO IMPORTANTE: Desmarque todas las casillas que hagan referencia a "datos de ejemplo", "usuarios de ejemplo", "ejemplares de prueba" o "bibliotecas de muestra" para garantizar una base de datos limpia.
  5. Alta de la Biblioteca: Indique un código corto para la sede (ej: CENTRAL) y el nombre oficial de la institución.
  6. Categoría de Personal: Código: STAFF | Descripción: Personal | Tipo de inscripción: Personal (Staff).
  7. Superbibliotecario Definitivo: Introduzca su nombre, número de carnet (ej: 1), el usuario para el trabajo diario y una contraseña robusta. Guarde esta contraseña.
  8. Tipos de Ítem: Código: LIV | Descripción: Libro.
  9. Reglas de Circulación: Establezca parámetros iniciales (ej: 3 a 5 libros por usuario, 14 días de préstamo, 2 renovaciones).

Al hacer clic en Terminar y comenzar a usar Koha, el sistema presentará el panel definitivo de administración listo para catalogar.

7. Publicación en Internet con Cloudflare Tunnel

Paso 1: Adquisición de Dominio o Subdominio Gratuito

  • Opción Recomendada (Dominio Institucional): Registre un dominio propio (ej: mibiblioteca.org) a través de Cloudflare o su registrador habitual.
  • Opción Gratuita (DigitalPlat): Genere un subdominio sin coste en DigitalPlat:
    1. Entre en domain.digitalplat.org y cree su cuenta.
    2. En Domain registration, seleccione una extensión gratuita (como .dpdns.org o .us.kg) y registre el nombre deseado (ej: mibiblioteca.dpdns.org).
    3. En la consola de Cloudflare, pulse Add a site, escriba el dominio registrado y escoja el Plan Gratuito (Free).
    4. Copie los dos servidores de nombres (Nameservers) provistos por Cloudflare y péguelos en el panel de DigitalPlat.

Paso 2: Configuración del Túnel y Vinculación en el Panel

  1. En Cloudflare Zero Trust, diríjase a Networks > Tunnels y pulse Create a tunnel.
  2. Asigne un nombre al túnel (ej: koha-servidor) y seleccione Debian 64-bit en la sección de instalación.
  3. Copie el token del túnel (la cadena extensa que empieza por ey...).
  4. En el terminal del servidor, inicie el panel con sudo options.sh y seleccione la Opción 14 (Acceso externo). Pegue el token: el servicio se instalará y quedará en ejecución de inmediato.

Paso 3: Asignación de Rutas Públicas (Public Hostnames)

En la pestaña Public Hostnames del túnel en Cloudflare, agregue dos rutas diferenciadas:

Entorno Subdominio Dominio Tipo (Service) URL Local de Destino
Staff (Administración) admin sudominio.org HTTP localhost:8080
OPAC (Catálogo Público) Dejar vacío sudominio.org HTTP localhost:80

El personal accederá a la intranet mediante https://admin.sudominio.org y los usuarios consultarán el catálogo a través de https://sudominio.org, protegidos mediante certificados SSL HTTPS automáticos de Cloudflare.

Complete Koha Installation and Configuration Manual

Structured guide focused on operational reliability: thorough OS preparation across 5 deployment scenarios, atomic single-line execution, and exhaustive coverage of all 25 features in the Koha Easy Install (Interactive Dashboard).

1. Understanding Koha ILS Architecture

Koha is the world's first open-source integrated library system (ILS). It runs natively on the enterprise LAMP stack (Linux, Apache, MariaDB, and Perl), serving as a centralized management backend that powers both library staff operations and public catalog discovery.

Dedicated Two-Port Topology

Unlike standard web applications that serve administrative and public areas under a single URL path, Koha strictly isolates its services into two distinct TCP ports on the Apache web server:

Environment Default Port Target Users Scope and Module Capabilities
Staff Client (Intranet) TCP 8080 Librarians, Catalogers, and System Administrators MARC21 bibliographic and authority cataloging, circulation operations (checkouts, check-ins, barcode renewal workflows), acquisitions, SQL reporting engine, patron fines, global preferences, and SIP2/Z39.50 service toggles.
OPAC (Public Catalog) TCP 80 Patrons, Students, Researchers, and the General Public Public search interface, dynamic faceted browsing, item holds, self-service renewals, public reading lists, and direct access to digital attachments.

This physical port separation allows precise perimeter security: port 80 (OPAC) can be exposed globally for public patron search, while port 8080 (Staff Client) remains locked down to internal library subnets or routed through authenticated cryptographic tunnels.

2. Operating System Preparation (5 Scenarios)

Koha is engineered natively for Debian and Ubuntu distributions. Follow only the scenario that matches your infrastructure:

Scenario 1: Dedicated Physical Server (Ubuntu Server)

Bare-metal production deployment on a physical machine (desktop workstation or rack server) dedicated exclusively to the library.

  • ISO Download: Download the official Ubuntu Server LTS image from Canonical's website.
  • Flashing the USB Drive with BalenaEtcher: Connect a USB drive of at least 4 GB to your personal workstation. Open BalenaEtcher, click Flash from file, select the Ubuntu Server ISO, choose the USB drive, and confirm flashing.
  • BIOS/UEFI Configuration: Connect the server to your router using a physical Ethernet cable. Power on the machine, press the Setup key (F2, Del, or F12), and set:
    • Secure Boot: Disabled (prevents third-party kernel module lockouts).
    • SATA Controller Mode: AHCI.
    • Restore on AC Power Loss: Power On (ensures the server boots automatically when power is restored).
    • Fast Boot: Disabled.
    • Halt On: No Errors (prevents boot halts when no physical keyboard is attached).
  • Ubuntu Server Installation:
    • Insert the USB drive, boot from it, and configure language and keyboard layout.
    • Keep the network interface on automatic DHCP via cable.
    • Under Guided storage configuration, select Use an entire disk.
    • Set the server hostname, administrative username (e.g., sysadmin), and a strong password.
    • MANDATORY: On the featured packages screen, navigate to Install OpenSSH server and press Space to toggle the [X] checkbox. Remote management will be unavailable without this package.
  • Finish the installation, remove the USB drive, and reboot the server.

Scenario 2: Cloud Server / VPS (Hetzner, DigitalOcean, AWS, etc.)

Hosted data center environment with high uptime, ideal for libraries without local infrastructure.

  • Create an account with your selected cloud provider and set up billing.
  • Deploy a new compute instance (Droplet / Cloud Compute Instance).
  • Operating System: Select either Ubuntu 22.04 LTS or Ubuntu 24.04 LTS (64-bit).
  • Mandatory Hardware Specs: Choose a plan with at least 2 vCPUs and 4 GB RAM. Instances with only 1 GB or 2 GB will crash during search index rebuilds and run out of memory under Apache/Plack.
  • Authentication: Configure a strong root password or attach your public SSH key.
  • Once provisioned, note down the public IPv4 address assigned to your instance.

Scenario 3: Desktop Linux Machine (Linux Mint or Ubuntu Desktop)

Single workstation deployment with a graphical interface, functioning as both an administrative terminal and an ILS host.

  • Download Linux Mint (Cinnamon Edition) or Ubuntu Desktop LTS.
  • Flash the ISO to a USB flash drive using BalenaEtcher.
  • Boot the computer from the flash drive and double-click the installer icon on the desktop.
  • Complete the graphical installation wizard, configuring language, keyboard, username, and password.
  • Operational Benefit: SSH is optional. Open the native terminal using Ctrl + Alt + T and run all commands directly on screen.

Scenario 4: Windows with VirtualBox Hypervisor

Running Ubuntu Server inside an isolated virtual machine on a Windows host.

  • Hardware Virtualization: Reboot Windows, enter your BIOS/UEFI, and enable Intel Virtualization Technology (VT-x) or SVM Mode (AMD).
  • Install VirtualBox and download the Ubuntu Server LTS ISO image.
  • VM Creation:
    • Click New. Name: Koha-Server. Type: Linux / Ubuntu (64-bit).
    • Select the downloaded Ubuntu Server ISO.
    • CRITICAL NOTICE: Check the box labeled Skip Unattended Installation. Unattended mode assigns generic randomized credentials and skips OpenSSH setup.
    • Allocate at least 4096 MB (4 GB) RAM and 2 CPU cores. Set virtual disk size to at least 25 GB.
  • Mandatory Network Setting (Bridged Adapter):
    • Open VM Settings and navigate to Network.
    • Change Attached to: from NAT to Bridged Adapter.
    • Select your active physical network adapter (Ethernet or Wi-Fi). This assigns the VM its own local IP address directly from your router.
  • Start the VM and complete standard Ubuntu Server setup, ensuring OpenSSH server is checked.

Scenario 5: Windows 10/11 using WSL2

High-performance native Linux kernel integration inside Windows, requiring no heavy hypervisors.

  • Ensure CPU virtualization (VT-x / AMD-V) is enabled in your BIOS.
  • Open the Windows Start Menu, search for PowerShell, right-click, and select Run as Administrator.
  • Execute the automated installation command:
    PowerShell (Admin)
    wsl --install -d Ubuntu
  • When prompted, reboot your PC. The Ubuntu terminal will launch automatically, prompting you to set a username and password.
  • Continuous Operation: No SSH required. Run commands directly within the WSL2 terminal window. Keep this terminal minimized in the background to ensure Koha background services remain active.

3. Terminal Access and SSH Connection

Access Rules: If you deployed on Desktop Linux (Scenario 3) or WSL2 (Scenario 5), open your local terminal and skip straight to Section 4. If you deployed on a Physical Server (Scenario 1), VPS (Scenario 2), or VirtualBox (Scenario 4), establish an SSH session from your workstation.

Determining the Server's Local IP Address

In your server terminal, run:

Server Terminal
ip a

Locate your primary interface (e.g., eth0, enp3s0, or wlan0). On the line beginning with inet, copy the address before the forward slash (e.g., for inet 192.168.1.105/24, the IP is 192.168.1.105). For cloud VPS instances, use the public IP provided in your cloud dashboard.

Connecting via PowerShell (Windows) or Terminal (macOS/Linux)

On your workstation, open your preferred command-line client and connect:

Local Workstation
ssh server_username@server_ip_address

Example: ssh sysadmin@192.168.1.105. On first connection, type yes and press Enter. Then enter your server password (characters will not be echoed on screen).

4. Downloading and Launching the Interactive Suite

Execute this single, atomic command chained with &&. It safely downloads the official script, grants execution permissions, and launches the TUI dashboard immediately:

Atomic Bootstrap Command
sudo curl -fsSL "https://raw.githubusercontent.com/BibliotecaPalotina/koha-easy-install/refs/heads/main/installer" -o /usr/local/bin/options.sh && sudo chmod +x /usr/local/bin/options.sh && sudo options.sh
Future Access: The executable is permanently installed at /usr/local/bin/options.sh. To manage your Koha server in the future, you never need to download anything from the internet again. Simply run:

sudo options.sh

5. In-Depth Guide to All 25 Dashboard Features

Option 1

Install Koha Server (Automated Base Deployment)

Performs a full, automated baseline deployment of Koha and all underlying system components without prone-to-error manual edits:

  • Pre-installation Validation: Validates root privileges, Debian/Ubuntu compatibility, DNS resolution against official Koha Community repositories, HTTPS connectivity, and checks for port conflicts on 80 and 8080.
  • Locales & Clock Synchronization: Configures mandatory UTF-8 character encoding (pt_BR.UTF-8 and en_US.UTF-8) and synchronizes the system clock with NTP pool servers via systemd-timesyncd.
  • Virtual Memory Allocation (4 GB SWAP): Creates and activates a permanent 4 GB swap file with 600 permissions in /etc/fstab, preventing Out-Of-Memory (OOM) kernel kills during peak cataloging and batch indexing.
  • APT Lock Shielding: Suspends background Ubuntu upgrade timers (such as unattended-upgrades) that cause DPKG lock collisions, implementing automated retries against transient mirror drops.
  • Core Dependencies: Installs essential production tools including glabels (crucial for printing spine labels and library patron barcodes), rclone, fail2ban, memcached, and XML parsers.
  • Official GPG Keys & Repositories: Configures signed apt sources for the Koha Community stable and Elasticsearch 7.x channels.
  • Isolated 'library' Instance: Provisions the MariaDB database, sets global defaults in koha-sites.conf, binds Apache virtual hosts, generates randomized DB secrets, and starts Plack and the Zebra daemon.
Option 2

View Access Credentials

Parses master credentials directly from /etc/koha/sites/library/koha-conf.xml. Displays the active database user (koha_library), initial setup password, and connection URLs formatted with the server's real IP address. Also writes this record to the secure file /root/credenciais_koha.txt with 600 permissions (root-only access).

Option 3

Restore Catalog from Backup (With Safety Rollback)

High-level restore pipeline for SQL dumps (.sql or .sql.gz) holding bibliographic data, patrons, and circulation history:

  • Native TUI File Browser: Provides an interactive file tree to locate backup archives across system disks or mounted USB drives (/media or /mnt).
  • Pre-flight Integrity Testing: Tests compressed archives against corruption with gzip -t and checks for valid SQL CREATE TABLE statements before touching existing databases.
  • Automatic Rollback Dump: Before purging current schemas, generates an immediate recovery snapshot (PRE-RESTAURACAO_date.sql.gz). If the target dump is invalid or contains fewer than 50 tables, the script triggers an automatic rollback to preserve library records.
  • Schema Migration & Index Rebuilding: Runs koha-upgrade-schema to upgrade older schemas to the current Koha release, flushes Memcached cache, and rebuilds catalog search indexes for the active engine (Zebra or Elasticsearch).
Option 4

Generate Manual Backup Now

Triggers an immediate, verified snapshot of the production database. Uses an interactive folder picker to define the target directory. Dumps are executed with --single-transaction --quick --routines --triggers in utf8mb4, ensuring ongoing catalog circulation is never locked during dump generation.

Option 5

Test Latest Backup (Dry-Run Restore)

Enforces the golden rule of systems administration: a backup only exists if it can be restored. Locates the most recent automated archive in /var/backups/koha_sql, creates an isolated temporary database (koha_teste_restauracao), decompresses the archive, and imports it. Validates table count, bibliographic records, and registered patrons before dropping the temporary database. Production data is never modified during this test.

Option 6

Install Koha Languages (International Language Packs)

Presents a comprehensive selector featuring over 70 official international language packs maintained by the global Koha Community (including European Portuguese pt-PT, Spanish es-ES, British English en-GB, French fr-FR, Italian, German, etc.):

  • Downloads and compiles translation strings using koha-translate --install.
  • Restarts Memcached and Plack workers to immediately register new web templates.
  • Prompts to immediately enable the language across global system preferences (language and OPACLanguages), exposing the language switcher in the OPAC footer and Staff login screen.
Option 7

Toggle Search Engine (Zebra ↔ Elasticsearch)

Manages complete transitions between Koha's supported search engines while maintaining data and XML integrity:

  • Zebra: Built-in C++ indexing daemon. Highly lightweight (uses ~1.5 GB less RAM), ideal for servers with 4 GB RAM. Operates using an incremental scheduled queue.
  • Elasticsearch: Enterprise Java search engine. Recommended for servers with 8 GB+ RAM. Offers real-time faceted browsing, fuzzy search, and superior performance for collections containing tens of thousands of records.
  • Safe Transition Pipeline: Updates koha-conf.xml via an atomic Python XML parser, tunes Elasticsearch JVM Heap limits based on total RAM, creates indices, and deploys a dedicated systemd service (koha-es-indexer@library) paired with a 5-minute watchdog cronjob to prevent queue stalls.
Option 8

Repair / Rebuild Indexing

Diagnostic and corrective maintenance for instances where newly cataloged titles fail to show up in search results:

  • For Elasticsearch: Validates port 9200 API health, confirms XML block presence, inspects pending background queues, and contrasts Elasticsearch doc counts with MariaDB record totals. Supports complete re-indexing (koha-elasticsearch --rebuild -d library) and orphaned job cleanups.
  • For Zebra: Terminates hung zebrasrv processes, removes stale lock files (.LCK and .pid), resets ownership to the Koha system user, and rebuilds indexes from scratch (koha-rebuild-zebra -f -v -b -a -r library).
Option 9

Server Sizing (Dynamic Memory Tuning)

Calibrates application throughput against total installed physical RAM. Adjusts PLACK_WORKERS (concurrent worker pool), memcached (session/template memory ceilings), and innodb_buffer_pool_size (database memory cache):

Profile Target Hardware Plack Workers Memcached Memory InnoDB Buffer Pool
Profile 1 Under 4 GB RAM 2 workers 64 MB 512 MB
Profile 2 4 to 8 GB RAM 3 workers 128 MB 768 MB
Profile 3 8 to 16 GB RAM 4 workers 128 MB 1 GB
Profile 4 Over 16 GB RAM 6 workers 256 MB 2 GB

Automated Rollback Protection: If an oversized profile causes MariaDB to fail during startup, the script instantly rolls back the configuration to the previous state, ensuring zero server downtime.

Option 10

Configure Cloud Backup (Google Drive via Rclone)

Secures automated nightly database backups offsite into encrypted cloud storage:

  • Express Mode (Google Drive): Streamlines remote connection. Generates an out-of-band authorization command (rclone authorize "drive" "..."). You copy and run this command on your desktop computer (where a web browser exists), log into the library's Google account, and copy back the resulting authorization token into the server terminal.
  • Manual Mode: Connects to Microsoft OneDrive, Dropbox, Amazon S3, Google Cloud Storage, SFTP, or Nextcloud using Rclone's native setup wizard.
  • Verification and Test Upload: Creates remote target directories (Backup_SQL_Koha and Backup_MARC_Koha), updates /etc/koha-easy-install/backup.conf, and allows triggering a dry-run backup to verify cloud upload immediately.
Option 11

Manage Scheduled Tasks (Crontab Schedules)

Opens the central cron configuration file (/etc/cron.d/koha_tasks) inside the Nano editor after taking a backup copy. Column syntax is clearly documented in header comments. Features an auto-healing routine: if the essential system PATH line is accidentally removed, the panel restores it before restarting the cron daemon, ensuring koha-shell jobs never fail silently.

Option 12

Configure Email Notices (SMTP)

Installs required SASL authentication modules and schedules daily circulation crons (overdue notices and message queue processing at 08:00 and 08:05). Provides a step-by-step tutorial on configuring outbound institutional SMTP relays (such as Google Workspace, Microsoft 365, or local mail servers) via Koha's web interface using STARTTLS and dedicated App Passwords.

Option 13

Create Super Librarian (Emergency Root Admin)

Securely provisions new system-wide administrators from the command line, ideal when web interface passwords are lost or staffing changes occur:

  • Automatically detects existing library branch codes and staff patron categories.
  • Sanitizes usernames to allow safe alphanumeric characters and escapes single quotes against SQL injection.
  • Enforces an 8-character minimum password length with confirmation prompts.
  • Secure Stdin Hashing: Hashes the password via Perl using Koha's internal authentication module (Koha::AuthUtils::hash_password). Password strings pass directly through standard input, preventing plaintext exposure in shell history (history) or process listings (ps aux).
Option 14

External Access (Cloudflare Tunnel Zero Trust)

Securely exposes the public catalog and administration interface over the internet on dynamic or residential internet connections without opening router ports or exposing static public IPs. Downloads and installs the official cloudflared connector service using a Zero Trust tunnel token and sets up automated systemd startup.

Option 15

Free SSL Certificate (Let's Encrypt / Certbot)

Designed for traditional server deployments possessing a static public IPv4 address and an open port 80. Installs certbot and the Apache plugin, guiding HTTPS certificate issuance with automated background renewals.

Option 16

Enable SIP2 and Z39.50 Protocols

Opens firewall ports and enables Koha's standardized library interoperability services:

  • Z39.50 Responder (Port 2100): Allows external libraries and union catalogs to search and download MARC records from your collection.
  • SIP2 Protocol (Port 6001): Enables integration with self-checkout kiosks, RFID security gates, and automated return sorters.
Option 17

Clock and Timezone Configuration

Interactive timezone selector offering quick presets for North America, Europe, and Latin America. Synchronizes system time and immediately restarts the cron daemon to prevent incorrect fine calculations caused by clock skew.

Option 18

Security Center

Server hardening and intrusion defense dashboard:

  • Fail2ban Status: Monitors blocked brute-force attack attempts across SSH and Apache security jails.
  • Staff Port 8080 Firewall: Restricts the administrative interface (port 8080) to localhost (127.0.0.1) and internal library subnets (192.168.x.x and 10.x.x.x), blocking direct external access from the public web.
  • Database Password Rotation: Generates a cryptographically strong 24-character password, updates MariaDB user authentication via ALTER USER, writes new credentials into koha-conf.xml, updates credentials files, and restarts Plack workers, testing local HTTP health to verify success.
  • UFW Firewall Rules: Inspects active listening rules and blocked ports.
Option 19

Update System and Schemas

Updates upstream OS and Koha repository packages safely. Executes database schema updates using koha-upgrade-schema library, purges obsolete packages, and triggers a full system validation check to ensure all services remain functional after upgrades.

Option 20

Koha Plugins Management

Enables or disables Koha's third-party plugin subsystem. Utilizes a Python-based XML parser to atomically set <enable_plugins>1</enable_plugins> inside koha-conf.xml, adjusts system preferences in the database, and sets ownership permissions for /var/lib/koha/library/plugins.

Option 21

Full System Validation

Comprehensive system health inspection engine. Analyzes network links, DNS resolution, running daemons, listening ports, local HTTP response codes (80 and 8080), XML syntax validity via xmllint, crontab conformity, backup file integrity and freshness, and active firewall policies.

Option 22

Detailed System Status

Live telemetry dashboard: displays the status of all core services (Apache, MariaDB, Memcached, Plack, Zebra, Elasticsearch, Cloudflared), active search engines, indexing background queue counts, RAM utilization, available disk space, and offsite backup sync states.

Option 23

Self-Update Dashboard

Atomic self-updating mechanism: fetches the latest codebase from GitHub into a temporary file in /tmp, verifies syntax integrity using bash -n, and atomically replaces /usr/local/bin/options.sh only if validation passes, retaining a timestamped backup of the previous version.

Option 24

Reboot Server

Performs a graceful, controlled restart of the host server after interactive confirmation, ensuring MariaDB transaction logs and disk caches are properly flushed.

Option 25

Exit

Exits the interactive management dashboard cleanly, restoring suspended APT background upgrade timers and freeing the shell session.

6. Completing the Browser Web Installer

Open a web browser on your workstation and navigate to administrative port 8080:

  • Scenarios 1, 2, and 4 (Physical Server / VPS / VirtualBox): Navigate to http://server_ip_address:8080 (e.g., http://192.168.1.105:8080).
  • Scenarios 3 and 5 (Desktop Linux / WSL2): Navigate directly to http://localhost:8080.

Complete the sequential setup wizard:

  1. Initial Authentication: Username: koha_library | Password: Paste the initial master password generated by Option 1 (if lost, retrieve it via Option 2 in the dashboard).
  2. Language Selection: Choose your preferred language and click Continue.
  3. Perl Dependencies & Cataloging Format: Confirm system module requirements and select the international standard MARC21.
  4. Default MARC21 Frameworks: Keep standard MARC21 cataloging frameworks selected. CRITICAL STEP: Uncheck all options referencing "sample data", "sample patrons", "sample items", or "sample libraries" to ensure a clean production database.
  5. Library Branch Registration: Enter a short Branch Code (e.g., MAIN) and the official Library Name.
  6. Patron Category Setup: Category Code: STAFF | Description: Staff | Enrollment Type: Staff.
  7. Permanent Superlibrarian User: Enter your full name, card number (e.g., 1), create your daily management username, and set a secure password. Record this password.
  8. Item Types: Item Type Code: BK | Description: Book.
  9. Circulation Rules: Define baseline loan policies (e.g., 3 to 5 items, 14-day loan period, 2 renewals).

Click Complete and Start Using Koha to finalize setup and access the production Staff dashboard.

7. Public Web Access via Cloudflare Tunnel

Step 1: Domain Name Provisioning

  • Recommended (Custom Domain): Register an institutional domain (e.g., mylibrary.org) via Cloudflare Registrar or any preferred registrar.
  • Free Subdomain (DigitalPlat): Create a free subdomain via DigitalPlat:
    1. Visit domain.digitalplat.org and create an account.
    2. Under Domain registration, pick an extension (such as .dpdns.org or .us.kg) and enter your library name (e.g., mylibrary.dpdns.org).
    3. In your Cloudflare dashboard, click Add a site, enter your subdomain, and choose the Free Plan.
    4. Copy the two Cloudflare Nameservers provided and paste them into DigitalPlat's nameserver fields.

Step 2: Tunnel Creation and Dashboard Linking

  1. In the Cloudflare Zero Trust dashboard, go to Networks > Tunnels and click Create a tunnel.
  2. Name the tunnel (e.g., koha-server) and choose Debian 64-bit on the installation screen.
  3. Copy the generated tunnel token (the long string starting with ey...).
  4. In your server terminal, open the management suite with sudo options.sh and choose Option 14 (External access). Paste the token: the service will be provisioned and started immediately.

Step 3: Public Route Hostname Mapping

Under the tunnel's Public Hostnames tab in Cloudflare, add two distinct hostnames:

Application Subdomain Domain Type (Service) Local Target URL
Staff (Administration) admin yourdomain.org HTTP localhost:8080
OPAC (Public Catalog) Leave empty yourdomain.org HTTP localhost:80

Your library staff will access the intranet at https://admin.yourdomain.org and patrons can browse the catalog at https://yourdomain.org, secured with automated Cloudflare SSL certificates.
